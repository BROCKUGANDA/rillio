   700→```
   701→
   702→Event envelope: `id`, `type`, `occurredAt`, `producer`, `tenantId`, `correlationId`, `schemaVersion`, `data`. Avoid raw descriptions, tokens and secrets in general-purpose events.
   703→
   704→Jobs: `csv.parse`, `csv.normalize`, `transactions.dedupe`, `transactions.categorize`, `provider.sync`, `provider.webhook.process`, `wallet.scan`, `wallet.refresh`, `portfolio.price.refresh`, `portfolio.snapshot`, `billing.webhook.process`, `payment.reconcile`, `notification.deliver`, `privacy.export`, `privacy.delete`, `analytics.aggregate`.
   705→
   706→Retry transient network errors, 429 and selected 5xx with exponential backoff + full jitter; respect `Retry-After`. Suggested bounded sequence 1/2/4/8/16 seconds plus jitter then DLQ, subject to provider limits. Do not retry validation/authorization/signature/business-rule failures. For submitted chain tx, query signature and blockhash validity before rebuild; never blindly submit another transfer. Every job has timeout, cancellation, attempt cap, structured error and idempotency key.
   707→
   708→Outbox: commit domain row and event in one DB transaction; publisher leases/publishes at-least-once; consumers dedupe through inbox; ack only after durable effect; DLQ replay requires reason, actor and audit record.

   710→# 14. Solana architecture
   711→
   712→## 14.1 Current client stack
   713→
   714→Use current official packages: `@solana/kit` for RPC/transactions/codecs/signers; `@solana/kit-plugin-rpc`; `@solana/kit-plugin-wallet`; `@solana/react`; generated `@solana-program/*` clients. Consider `@solana/keychain` only for a real backend signing requirement after a security design; do not add backend signing by default. Pin compatible versions and re-check the official docs at implementation time.
   715→
   716→## 14.2 Read-only wallet path
   717→
   718→Browser discovers Wallet Standard wallets → user selects → client obtains public address/capabilities → backend stores association after appropriate proof → scanner reads native/token accounts → parser validates token program/mint/decimals/owner → metadata service checks provenance/spam → pricing adapter returns quotes → portfolio snapshot persists provenance → UI displays stale/unverified/unpriced states.
   719→
   720→Never infer token authenticity from symbol/logo. Mint address and token program are canonical identifiers.
   721→
   722→## 14.3 RPC resilience
   723→
   724→- No public shared RPC in production.
   725→- Use production RPC with documented limits plus independent fallback.
   726→- Separate reads, submissions and websocket workloads as necessary.
   727→- Deadlines, rate limits, circuit breakers.
   728→- Persist signature/slot cursors and resume without gaps.
   729→- Reconcile indexer state with RPC periodically.
   730→- Track provider lag, websocket disconnects and error rates.
   731→- If sources disagree, mark degraded; do not choose an arbitrary balance.
   732→
   733→## 14.4 Future transaction execution
   734→
   735→Only after launch gates: build from trusted versioned instructions; validate destination, mint, amount, decimals, fee payer and account ownership; simulate; estimate priority fee with visible maximum; show a human-readable summary; user signs; submit via production RPC; persist signature/blockhash; track `submitted → processed → confirmed → finalized` or failed/expired/unknown; reconcile balances; resolve unknown before retry. Solana fees can still be charged on failed transactions, so UI must disclose that possibility.
   736→
   737→## 14.5 Custom program policy
   738→
   739→No Anchor/Rust program for MVP. Existing primitives and backend services are sufficient. Add a custom program only when a concrete requirement cannot be met otherwise. Then document authority/account constraints/upgrade authority/emergency pause; add invariant, fuzz and adversarial tests; use LiteSVM / Surfpool; reproducible build and verified deployment; independent review before mainnet.
   740→
   741→## 14.6 Token-2022 / RWA
   742→
   743→Extensions are optional and some combinations are incompatible. Choose only after requirements mapping. Transfer hooks add program execution to transfers; don't use as decoration or speculative tokenomics. For RWA, verify issuer identity, legal rights, custody, transfer restrictions, valuation, distribution eligibility, redemption, insolvency treatment and jurisdiction. Chain data alone does not establish these facts.
